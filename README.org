#+TITLE: ghostel-tmux

tmux control mode for Emacs, built on [[https://github.com/dakra/ghostel][Ghostel]].

=ghostel-tmux= connects to a tmux session via control mode (=tmux -CC=) and
shows each tmux pane as a ghostel buffer: full VT engine, scrollback,
isearch, occur, copy mode and evil integration all work on pane content.
The panes of a tmux window are Emacs window splits, and the tmux windows are
tabs in the tab line.

* Requirements

- tmux 3.0 or later.
- [[https://github.com/dakra/ghostel][Ghostel]] 0.62.0 or later, with its native module.

* Commands

| Command                                         | What it does                                                                            |
|-------------------------------------------------+-----------------------------------------------------------------------------------------|
| =M-x ghostel-tmux-new=                            | Create or attach to a session by name.                                                   |
| =M-x ghostel-tmux-attach=                         | Pick a running session via =completing-read= and attach.                                 |
| =M-x ghostel-tmux-detach=                         | Detach the current session.  Pane buffers stay as read-only snapshots.                  |
| =M-x ghostel-tmux-capture=                        | One-shot snapshot: dump a single pane's scrollback into a fresh buffer (no live link).  |
| =M-x ghostel-tmux-next-pane= / =ghostel-tmux-prev-pane= | Cycle through sibling panes, across tmux windows (=C-t C-n= / =C-t C-p=).              |
| =M-x ghostel-tmux-switch-pane=                    | =completing-read= picker over sibling panes (=C-t s=).                                    |
| =M-x ghostel-tmux-restore-split=                  | Split the window's tmux window again as tmux lays it out (=C-t r=).                      |
| =M-x ghostel-tmux-reset=                          | Escape hatch: reset tmux state when the protocol parser is wedged.                      |

With a remote =default-directory=, =ghostel-tmux-new=, =ghostel-tmux-attach= and
=ghostel-tmux-capture= run =ghostel-tmux-program= on that host through TRAMP.  A
tmux server started this way keeps the environment of TRAMP's shell, such as
=PAGER=cat=; start the server on the host first to avoid that.

* Takeover: =tmux -CC= in a ghostel shell

#+begin_src emacs-lisp
(ghostel-tmux-takeover-mode 1)
#+end_src

With the mode on, a =tmux -CC new= or =tmux -CC attach= typed in a ghostel
shell turns that shell's buffer into the controller.  This works in
native-PTY, Emacs-PTY and TRAMP sessions alike, and for =tmux -CC attach=
typed inside an ssh session.  The first pane shows up in the window the
shell was in, sized to it, and the tab line lists the session's windows (its
panes with =ghostel-tmux-split-windows= nil).
While tmux is attached, what is typed in the shell buffer goes to tmux as
commands, so a window switching to it shows its previous buffer instead,
and =M-x ghostel= starts a new shell.

When tmux leaves control mode (=M-x ghostel-tmux-detach=, =C-t d= in a pane, or
anything else that ends the session), every window showing a pane goes
back to the shell buffer and the pane buffers stay as read-only snapshots.

A tmux client that dies without detaching (=kill -9=, a crash) leaves control
mode open until the shell prints an escape sequence, which most prompts
do.  With a plain prompt such as macOS's =/bin/bash=, run
=M-x ghostel-tmux-reset= and press =C-l=.

A raw escape sequence in tmux's output, such as =run-shell= printing colors
from =C-t :=, ends control mode as well: tmux is told to leave, the panes
become snapshots, and the shell shows the end of the control-mode stream.

With the mode off, =tmux -CC= in a ghostel shell shows nothing until tmux
exits, as in any terminal without control-mode support.

** Shell wrapper

=shell/= has an optional =tmux= wrapper for bash, zsh, fish and nushell that
adds =-u -CC= to the subcommands that attach (=tmux new=, =tmux attach=, =tmux a=,
or bare =tmux=) and passes everything else through, also =tmux new -d=, which
has no client to take over, =tmux -c=, and any =tmux= in a tmux pane.  In bash,
zsh and fish a =tmux= alias or function defined before sourcing it stays in
place of the wrapper.  Source it in ghostel only:

#+begin_src sh
# bash; for zsh use ghostel-tmux.zsh
[[ "${INSIDE_EMACS%%,*}" = 'ghostel' ]] && source /path/to/ghostel-tmux/shell/ghostel-tmux.bash
#+end_src

#+begin_src fish
string match -q 'ghostel*' "$INSIDE_EMACS"; and source /path/to/ghostel-tmux/shell/ghostel-tmux.fish
#+end_src

#+begin_src nushell
# config.nu; the wrapper checks INSIDE_EMACS itself
source /path/to/ghostel-tmux/shell/ghostel-tmux.nu
#+end_src

Bypass it with =command tmux ...= (=^tmux ...= in nushell), or by setting
=GHOSTEL_TMUX_NO_CC= before sourcing it (at any time in nushell).

* Prefix bindings

Pane buffers bind =C-t= (customizable via =ghostel-tmux-prefix-key=, e.g. to =C-b=)
as a tmux-style prefix.  These translate into tmux control-mode commands sent
over the active session, so they work the same whether you started tmux via
=ghostel-tmux-new= or by typing =tmux -CC= in a shell.

| Key sequence | tmux command          | Action                                        |
|--------------+-----------------------+-----------------------------------------------|
| =C-t "=        | =split-window -v=       | Split current pane horizontally (new below). |
| =C-t %=        | =split-window -h=       | Split current pane vertically (new right).   |
| =C-t c=        | =new-window=            | Create a new window.                         |
| =C-t x=        | =kill-pane=             | Kill the current pane.                       |
| =C-t z=        | =resize-pane -Z=        | Zoom the current pane, or unzoom (splits).   |
| =C-t &=        | =kill-window=           | Kill the current window.                     |
| =C-t n=        | =next-window=           | Cycle to the next window.                    |
| =C-t p=        | =previous-window=       | Cycle to the previous window.                |
| =C-t o=        | =select-pane -t :.+=    | Cycle to the next pane.                      |
| =C-t C-n=      | -                     | Next pane in tab order, across windows.      |
| =C-t C-p=      | -                     | Previous pane in tab order, across windows.  |
| =C-t s=        | -                     | Pick a pane with =completing-read=.          |
| =C-t r=        | -                     | Split the window again as tmux lays it out.  |
| =C-t ,=        | =rename-window=         | Prompt and rename the current window.       |
| =C-t $=        | =rename-session=        | Prompt and rename the current session.      |
| =C-t 0= ... =9=  | =select-window -t :N=   | Jump to window N.                            |
| =C-t :=        | (prompt for any cmd)  | Run a tmux command and show its output.      |
| =C-t d=        | -                     | Detach (=ghostel-tmux-detach=).                |
| =C-t ?=        | -                     | Describe the prefix map.                     |
| =C-t C-t=      | -                     | Send a literal prefix byte to the program.   |

The map is =ghostel-tmux-prefix-map=; rebind individual keys however you like.
With =repeat-mode=, =C-n= and =C-p= repeat after =C-t C-n= or =C-t C-p=.

* Split windows

A tmux window of several panes shows them all at once: the Emacs window
showing one of its panes is split to match tmux's layout, and tmux lays the
panes out in that window's size.  Windows beside it stay as they are.  A
split from Emacs (=C-t %=, =C-t "=), from another client or from a command
such as =select-layout= splits the Emacs window too, and each layout tmux
settles on moves the window edges to its pane sizes.

Selecting a window of the split makes its pane tmux's active pane, and a pane
tmux makes active (=C-t o=, another client) gets the selection while a window
of the split has it.  Switching tmux windows (=C-t n=, =C-t 1=) shows the
other window in the place of the split.

Dragging a divider or a mode line between windows of the split, or resizing
one with =C-x {= and the like, resizes the pane in tmux.  Swapping windows of
the split (=windmove-swap-states-left= and the like) swaps their panes in tmux
(=swap-pane=), and panes swapped in tmux (=C-b {=) show in their new places.

=C-t z= zooms the current pane to the whole split, and shows all panes of its
window again.  Deleting all windows of a split but one (=C-x 1=) zooms its
pane, and deleting some builds the split again.  A window of the split can
show another buffer for a while and keeps its place until tmux
changes the window's layout, and a window split off
one of its windows (=C-x 3=) gets a place beside the split.
=M-x ghostel-tmux-restore-split= (=C-t r=) shows the split as tmux lays it out
again: its windows show their panes, lost windows come back, and a zoomed pane
is unzoomed.  Run from a window showing a pane outside the split, it moves the
split there.

tmux has one size per client, for all windows of its session: of two splits
of one session shown at once, the one not of the current tmux window shows
its panes at the other's size, and a divider dragged in it snaps back.

With =ghostel-tmux-split-windows= nil, an Emacs window shows one pane, which
tmux zooms when its window has several.

* Tab line

Pane buffers have a tab line with a tab per tmux window.  Click a tab to show
that window in the Emacs window clicked, or where Emacs shows it already, or
hit =C-t n= / =C-t p=.  A split has one tab line over its top row of windows,
each showing its part, and no tab line further down.  =C-t C-n= / =C-t C-p=
and =C-t s= go to a pane of any window.

With =ghostel-tmux-split-windows= nil, the tabs are the session's panes, and a
click switches panes in the same window.

* Sizing

A pane's terminal follows the Emacs windows showing it, like any ghostel
buffer.  Each new size is sent to tmux with =refresh-client -C cols,rows=,
so the server lays the panes out for the real client size.  For a split, the
size is what the split windows show, with the column or row tmux puts
between panes, and each pane keeps the size tmux gives it.  Where Emacs
spends more between two windows than tmux's separator, such as two borders
in a nested split, the window beside them can have a column or row more
than its pane.

* Floating panes

The floating panes of tmux 3.8 (=new-pane=, =break-pane -W=) are in no window
layout, so they get no buffer, and a pane that turns floating loses its buffer.
With a floating pane active, Emacs keeps the tiled panes it shows, or shows the
window's first tiled pane.  With =ghostel-tmux-split-windows= nil, in a window
with several tiled panes it zooms that pane, which takes the selection from the
floating pane and hides it from other clients too.

A current window that holds only floating panes has nothing to show.  On attach,
on takeover and when the pane shown goes away, Emacs moves the session to a
window with a tiled pane.  A takeover that starts in a session with no tiled pane
at all stays on the hidden shell.

* Customization

| Option                              | Effect                                                                              |
|-------------------------------------+-------------------------------------------------------------------------------------|
| =ghostel-tmux-program=                | tmux executable.  Default ="tmux"=.                                                  |
| =ghostel-tmux-prefix-key=             | Prefix key in pane buffers.  Default ="C-t"=.                                        |
| =ghostel-tmux-split-windows=          | Show the panes of a tmux window as Emacs splits.  Default =t=.                       |
| =ghostel-tmux-history-lines=          | Scrollback lines to backfill via =capture-pane= on attach.  Default =10000=.          |
| =ghostel-tmux-default-rows= / =-cols=   | Initial pane terminal size before the layout-resize fires.  Default =40= x =120=.     |
| =ghostel-tmux-buffer-name-function=   | Customize pane buffer naming.  Called with =(SESSION WINDOW PANE-ID)=.               |

* Development

=make all= byte-compiles, runs the unit tests and the shell wrapper test,
and lints.  =make test-native= runs the tests that need ghostel's native
module, built in =GHOSTEL_DIR= (default =~/.emacs.d/lib/ghostel=).

=make test-elate= drives a real tmux from sandboxed Emacs sessions with
[[https://github.com/dakra/elate][elate]].  It needs the native module, tmux, and bash, zsh, fish and
nushell at the paths named in the scenarios.  Each run has a private tmux
server under =/tmp/ghostel-tmux-elate-*=.

| Scenario                     | Covers                                                                   |
|------------------------------+--------------------------------------------------------------------------|
| =test/elate/takeover.json=     | =tmux -CC= in a shell, per host shell and PTY backend, and every way out.  |
| =test/elate/panes.json=        | Keys, splits, switching, windows, scrollback, a second client, closing, with one pane per Emacs window. |
| =test/elate/subprocess.json=   | =ghostel-tmux-attach=, =ghostel-tmux-new= and =ghostel-tmux-capture=, with one pane per Emacs window. |
| =test/elate/splits.json=       | Panes as Emacs splits: selection, swaps, restoring, zoom, resizing, switching windows, closing. |

One variant of one scenario:

#+begin_src sh
GHOSTEL_DIR=~/.emacs.d/lib/ghostel \
  elate run --emacs "$(command -v emacs)" --variant fish-native test/elate/takeover.json
#+end_src
